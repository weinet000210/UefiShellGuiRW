# Architecture

## Layers

```text
+--------------------------------------------------------------+
| UefiShellGuiRW.efi                                           |
|  Shell/   main frame: menu bar, toolbar, MDI desktop,        |
|           status bar, command table, key handling            |
|  Views/   content of each child window (one file per module) |
|           Phase 3: PCI, Memory, I/O, Index/Data, CMOS, MSR   |
|           Phase 4: PCIe Tree, ACPI, SMBIOS, USB              |
|           Phase 5: EC, SIO, COM, SMBus/SPD, Storage, EDID    |
|  Widgets/ (Phase 2) HexGrid, BitFieldView, TreeView,         |
|           PropertyTable, dialogs                             |
+------------------------------+-------------------------------+
| RwCoreLib (Phase 1, no LVGL) | LVGLUefiGuiPkg (submodule)    |
|  PCI, Mem, IO, MSR, CMOS,    |  UefiGuiLib, LVGL v9.6,       |
|  EC, SIO, SMBIOS, ACPI, AML, |  GOP display, keyboard,       |
|  USB, UART                   |  mouse, event loop            |
+------------------------------+-------------------------------+
| UEFI Boot Services and protocols                             |
+--------------------------------------------------------------+
```

Rules:

- RwCoreLib never includes LVGL headers; it can be tested on its own.
- Views reach hardware only through RwCoreLib. Its rules, modules and tests
  are in [RwCoreLib.md](RwCoreLib.md).
- Every menu entry and toolbar button is a command in `Shell/Commands.c`
  (`RW_COMMAND_ID`). Menus and the toolbar only list command IDs, so a
  module is added in one place and gets its menu entry, toolbar button,
  window title and icon from the table.

## Main frame (Phase 0)

| Part | File | Notes |
|---|---|---|
| Menu bar | `Shell/MenuBar.c` | File, Access, Specific, Window, Help. Drop-downs on `lv_layer_top()`; a transparent backdrop below the bar closes them. Window menu lists open windows. |
| Toolbar | `Shell/Toolbar.c` | 20x20 icons, flat buttons with hover/pressed states; disabled commands are grayed out. Hover text goes to the status bar. |
| Desktop | `Shell/MainFrame.c`, `Shell/Mdi.c` | MDI child windows: caption (gradient, icon, title, min/max/close), drag, resize grip, activate on click, cascade, tile, minimize to the bottom row, maximize to the desktop. |
| Status bar | `Shell/StatusBar.c` | Hint, active window, resolution and version. |
| Icons | `Shell/Icons.c` | Generated by `scripts/gen-icons.py` (original drawings, ARGB8888). |

A module opens one window; running its command again brings that window to
the front (as RW-Everything does).

## Data source (Phase 1, used by the Phase 2 widgets)

Hex views are one widget over an interface:

```c
typedef struct {
  CONST CHAR8  *Name;
  UINT64       Size;
  EFI_STATUS   (*Read)  (VOID *Ctx, UINT64 Offset, UINTN Width, UINT64 *Value);
  EFI_STATUS   (*Write) (VOID *Ctx, UINT64 Offset, UINTN Width, UINT64 Value);
  BOOLEAN      (*IsDangerous) (VOID *Ctx, UINT64 Offset);   // confirm before writing
} RW_DATA_SOURCE;
```

PCI config space, memory, I/O, CMOS, EC and Super I/O LDN registers each
provide one data source; the HexGrid handles display, editing, width
switching, change highlighting and auto refresh for all of them.

## Testing

`UefiShellGuiRW.efi -selftest` drives the frame through the same functions
the mouse and keyboard reach (commands, toolbar click events, the key
handler) and checks window geometry and state. CI runs it in QEMU for DEBUG
and RELEASE and keeps a screenshot.
Widget details: [Widgets.md](Widgets.md).

Module windows: [Views.md](Views.md).
